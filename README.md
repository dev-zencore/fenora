# Finora

Минималистичное офлайн-приложение для личных финансов на Android. Проект рассчитан на открытый исходный код и не использует Manus-сервисы, аккаунты, рекламу, Google Analytics или обязательную облачную синхронизацию.

## Что уже есть

- обзор всех счетов и наличных;
- расходы и доходы через быстрый экран добавления;
- список операций;
- расчёт суммы, доступной сегодня;
- цели накопления;
- экран настроек с будущими точками подключения Obsidian;
- локальное сохранение данных через AsyncStorage;
- тёмный минималистичный интерфейс с автоматической темой в планах развития;
- GitHub Actions для сборки при публикации тега `v*`.

## Локальный запуск

Требуются Node.js 22+ и Android Studio/Android SDK для запуска на эмуляторе или устройстве.

```bash
npm install
npx expo start
```

После запуска нажмите `a` в терминале Expo или выполните:

```bash
npm run android
```

## Сборка через GitHub

1. Создайте публичный или приватный репозиторий и загрузите проект.
2. Включите GitHub Actions.
3. Создайте тег версии:

```bash
git add .
git commit -m "Initial Finora app"
git tag v0.1.0
git push origin main --tags
```

Workflow `.github/workflows/android.yml` установит зависимости, сгенерирует нативный Android-проект через Expo Prebuild, соберёт устанавливаемый debug APK через Gradle и создаст GitHub Release с APK и архивом исходников. Для полноценного подписанного production APK/AAB позже можно добавить собственный Android keystore в GitHub Secrets; в репозитории ключи и пароли не хранятся.

## Конфиденциальность

Finora не отправляет финансовые данные в сеть. В проекте нет трекеров, рекламных SDK, Google Analytics и серверной базы данных. Данные хранятся локально на устройстве. Интеграция с Obsidian должна работать через выбранный пользователем локальный vault и записывать данные в ежедневные заметки `periodic/daily`, сохраняя существующий YAML frontmatter и тело заметки.

## План интеграции с Obsidian

Следующий модуль должен позволить выбрать vault, путь к шаблону в `templates`, папку `periodic/daily`, а также сопоставить существующие YAML-поля с операциями приложения. Новые записи должны добавляться только в YAML, не изменяя тело ежедневной заметки. Если финансовые поля отсутствуют, приложение сначала показывает предварительный просмотр и добавляет их только после согласия пользователя.
